## Findings

| ------ | ----- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-01 | open  | The credentials for the `--User`- and `--Password`-options are passed as plaintext command-line arguments.                      | On most operating systems the command-line arguments of a running process are readable by other local processes and users (process-table), and they are commonly persisted in the shell-history, so the password can be disclosed to other local users. | By-design limitation of the current CLI-interface (the `--Password`-option is documented in the ReadMe). A mitigation would be to accept the password via an environment-variable or via stdin instead of as a visible argument. Source: `Epew/Epew/Verbs/RunCLI.cs` (`Password`-option), consumed in `Epew/Epew/Runner/RunWithArgumentsFromCLI.cs`. Severity: low (local exposure only). |
| BUG-01 | open  | The `--PrintErrorsAsInformation` (`-i`) option is declared and documented but never evaluated during the execution.             | The documented behaviour ("treat errors as information") has no effect; stderr is always handled the same way, so users relying on this switch get a behaviour that differs from the documentation.                                                     | Defined in `Epew/Epew/Verbs/RunCLI.cs` and never referenced in `Epew/Epew/Runner/RunWithArgumentsFromCLI.cs`. Non-trivial because implementing it requires adjusting how stderr is logged and treated. Verified to still be present in the current code.                                                                                                                                  |
| OTH-01 | open  | The top-level `catch` in `Program.Main` swallows every exception and returns the fatal-error exitcode without logging anything. | An unexpected error terminates Epew with exitcode 2147393801 and no output, which makes such failures hard to diagnose.                                                                                                                                 | Located in `Epew/Epew/Helper/ProgramStarter.cs` (`Main`). The inner execution-layer does log its own errors, so this only concerns errors outside `RunImplementation`. Severity: low.                                                                                                                                                                                                     |
